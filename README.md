# 스트레칭펫 (StretchPet)

화면 위를 돌아다니는 작은 캐릭터가 일정 시간마다 스트레칭을 하라고 알려주는 데스크톱 펫
프로그램입니다. 정해진 "집중 시간"이 끝나면 캐릭터가 스트레칭 동작을 안내합니다.

이 문서는 프로그램을 쓰는 방법과, 새로 추가된 "메신저 알리미" 기능의 사용법·앞으로 할 일을
정리합니다.

---

## 사용법 (일반 사용자용)

### 기본 사용

- 프로그램을 실행하면 화면 위에 캐릭터가 나타나고, 화면 아래쪽 작업표시줄 구석의
  트레이 아이콘(시스템 트레이, 화면 오른쪽 아래 작은 아이콘 모음)에도 스트레칭펫 아이콘이
  뜹니다.
- 트레이 아이콘을 **우클릭**하면 메뉴가 나옵니다. 여기서 집중 시간(50분 집중 / 25분 집중)을
  고르거나, 시작 프로그램 등록, 종료 등을 할 수 있습니다.

### 메신저 알리미 기능

"메신저 알리미"는 브리티 메신저(교육청 업무용 메신저)로 새 쪽지가 오면 캐릭터가 말풍선으로
알려주고, 그 내용을 미요플래너 서버로 보내서 담당 선생님이 검토 후 등록할 수 있게 해주는
기능입니다. 사용 방법은 다음과 같습니다.

1. **트레이 아이콘 우클릭 → "미요플래너 로그인"** 을 클릭합니다. 기본 웹 브라우저가 열리면서
   구글 로그인 화면이 나타납니다. 미요플래너 계정(구글 계정)으로 로그인하세요. 로그인에
   성공하면 메뉴 항목이 "미요플래너 로그아웃"으로 바뀝니다.
2. **트레이 아이콘 우클릭 → "메신저 알리미: 꺼짐"** 항목을 클릭해서 켭니다.
   - 처음 켤 때는 "브리티 쪽지 내용이 요약을 위해 외부 AI(Gemini)로 전송됩니다. 계속할까요?"
     라는 동의 확인창이 뜹니다. **"동의하고 켜기"** 를 눌러야 기능이 켜집니다. (한 번 동의하면
     다음부터는 다시 묻지 않습니다.)
   - 로그인하지 않은 상태에서는 "메신저 알리미" 항목 자체가 회색으로 흐리게 표시되어 클릭할
     수 없습니다. 먼저 1번 단계로 로그인부터 완료하세요.
3. 기능이 켜지면 메뉴에 **"테스트 쪽지 보내기 (개발용)"** 항목이 추가로 나타납니다. 이걸
   클릭하면 실제 브리티 쪽지가 온 것처럼 테스트용 쪽지 한 건이 발생하고, 캐릭터가 말풍선으로
   보여줍니다. 이 항목은 아래 "지금 한계" 항목에서 설명하듯 실제 브리티 쪽지 대신 테스트용으로
   동작을 확인하는 용도입니다.
4. 확인하지 않은 쪽지가 있으면 트레이 아이콘에 마우스를 올렸을 때 "확인 대기 N건"으로 표시되고,
   메뉴의 "메신저 알리미: 켜짐" 항목에도 대기 건수가 같이 표시됩니다. 다 확인했으면
   트레이 메뉴의 "확인 대기 건수 지우기"로 0으로 되돌릴 수 있습니다.

### 지금 한계 — 실제 브리티 쪽지는 아직 읽지 않습니다

**중요:** 지금 버전은 브리티 메신저를 실제로 읽어오지 않습니다. 트레이 메뉴의
"테스트 쪽지 보내기 (개발용)"를 눌러야만 정해진 테스트 문구 하나가 쪽지처럼 발생합니다.
이건 실제 기능이 완성되기 전까지 알림·전송 흐름 전체(말풍선 표시 → 서버 전송 → 선생님 검토)가
잘 동작하는지 확인하기 위한 임시 장치입니다.

실제로 브리티 메신저 창을 읽어오는 기능(윈도우 접근성 API를 이용한 방식)은 다음 단계로
남아 있습니다. 나중에 이 기능을 추가할 때는:

- `src/main/brity/reader.ts`에 정의된 `BrityReader` 인터페이스(쪽지가 오면 `start`로 등록한
  콜백을 호출하고, `stop`으로 멈추는 규격)를 구현하는 새 클래스를 만들고,
- `src/main/main.ts`에서 두 줄만 바꾸면 됩니다 — 맨 위의
  `import { createFakeBrityReader } from './brity/fakeReader';` 줄을 새 구현을 가져오는
  import으로, 그리고 지금 쓰고 있는 `createFakeBrityReader()` 호출을 그 새 클래스로
  바꿔치기하면 됩니다.

그 외 코드(말풍선 표시, 서버 전송, 재시도 큐 등)는 이 인터페이스만 보고 동작하므로 **전혀
손댈 필요가 없습니다.** "테스트 쪽지 보내기 (개발용)" 메뉴 항목은 리더가
`triggerTestMessage()`를 가진 경우에만 나타나므로, 실제 리더로 바꾸면 자동으로 사라집니다.

## 설정값 (서버 주소 등)

메신저 알리미가 쪽지를 보낼 미요플래너 서버 주소와, 로그인에 쓰는 구글 클라이언트 ID는
아래 두 곳 중 하나에서 읽어옵니다. 개발 중에 설정한 값이 있으면 그 값이 우선 적용되고,
없으면 프로그램에 미리 구워둔 배포용 기본값을 씁니다.

1. **개발용 — 환경변수** (`MIYO_SERVER_URL`, `MIYO_GOOGLE_DESKTOP_CLIENT_ID`)

   프로그램은 `.env` 파일을 읽지 않습니다(dotenv를 쓰지 않습니다). 아래처럼 실제
   환경변수를 설정한 터미널에서 실행해야 값이 적용됩니다. 값 예시는 저장소의
   `.env.example`에 정리해 두었습니다.

   윈도우 PowerShell (이번 실행에만 적용):

   ```powershell
   $env:MIYO_SERVER_URL = "http://localhost:3001"
   $env:MIYO_GOOGLE_DESKTOP_CLIENT_ID = "여기에-클라이언트-ID"
   npm start
   ```

   윈도우 cmd.exe:

   ```bat
   set MIYO_SERVER_URL=http://localhost:3001
   set MIYO_GOOGLE_DESKTOP_CLIENT_ID=여기에-클라이언트-ID
   npm start
   ```

   계정에 영구 저장하려면 `setx MIYO_SERVER_URL "http://localhost:3001"`처럼 하고
   터미널을 새로 엽니다.

2. **배포용 — `package.json`의 `miyoConfig`** (설치 파일을 만들 때 이 값이 함께 포함됩니다)

   ```json
   "miyoConfig": {
     "serverUrl": "https://miyo-planner.vercel.app",
     "desktopClientId": "280309938828-1tbv8eqqh1gmfbba51qfg4sig6qchcda.apps.googleusercontent.com"
   }
   ```

   여기 적힌 클라이언트 ID는 비밀번호가 아닌 공개 식별자(PKCE 방식이라 안전)라서 그대로
   커밋해도 괜찮습니다.

## 개발자용 정보

### 빌드/실행 명령 (package.json 기준)

| 명령 | 설명 |
|---|---|
| `npm run build` | 메인 프로세스·렌더러 코드를 TypeScript로 컴파일 |
| `npm start` | 빌드 후 Electron으로 실행 |
| `npm test` | vitest로 단위 테스트 실행 |
| `npm run test:smoke` | 빌드 후 스모크 테스트 스크립트 실행 |
| `npm run slice-sprites` | 캐릭터 스프라이트 이미지 슬라이싱 스크립트 |
| `npm run package` | 빌드 후 electron-builder로 윈도우용 포터블 실행파일 생성 |

### 브리티 실제 읽기 기능을 추가하려면

1. `src/main/brity/reader.ts`의 `BrityReader` 인터페이스(`start(onMessage)` / `stop()`)를
   구현하는 새 클래스를 작성합니다. 윈도우 접근성(UI Automation) API로 브리티 메신저 창을
   읽는 방식을 참고할 수 있습니다 (`src/main/brity/fakeReader.ts`가 지금 이 인터페이스를
   흉내만 내는 자리표시자 구현입니다).
2. `src/main/main.ts`에서 두 줄을 바꿉니다: 파일 맨 위의
   `import { createFakeBrityReader } from './brity/fakeReader';` import 줄과,
   `const brityReader: BrityReader = createFakeBrityReader();` 호출 줄을 각각 새 구현으로
   바꿉니다.
3. 그 외 파일(`ingestClient.ts`, `retryQueue.ts`, `messengerAlertService.ts`, `tray.ts` 등)은
   전부 `BrityReader` 인터페이스와 `BrityMessage` 타입만 보고 동작하므로 수정할 필요가
   없습니다. `main.ts`의 `brityReader` 변수 타입도 `BrityReader`이고, 개발용
   `triggerTestMessage()`는 런타임에 있는지 확인해서 있을 때만 트레이에 연결하므로,
   `BrityReader`만 구현한 실제 리더를 넣어도 컴파일·실행이 그대로 됩니다.
4. 구현체는 `start()`/`stop()`이 반복 호출돼도 안전해야 합니다(감시기 중복 생성 금지).
   서비스 쪽에서도 중복 호출을 막지만, 인터페이스 규약으로도 요구합니다.
